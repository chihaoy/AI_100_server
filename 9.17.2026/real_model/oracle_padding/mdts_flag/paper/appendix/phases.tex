Table~\ref{tab:phases} classifies the aggregation's operations by phase. Both formulations gather about the same bytes
(898 and 924\,MiB) and keep them on their SoC: cross-SoC traffic in the MoE layer is 14.0 and 12.1\,MiB. They differ in
the sum to the per-SoC partials. The lane-indexed formulation sums each token tile over a SoC's 16 lanes, which sit on 16
different cores, so every tile's sum pulls its operands from all cores; its 16 tiles span 3.0--3.6\,ms per SoC, and their
windows add up to 4.6--5.6\,ms with only 1.7--2.0\,ms of overlap. Step 5 sums each token's $k$ rows on the core that owns
the token. Its index build is heavier, but it runs while the expert stages do. In the profile, the window from the last
expert GEMM to the end of the final sum is about 1.9\,ms longer per layer for the lane-indexed formulation; the
uninstrumented full models differ by 1.1\,ms per layer (401.7 against 349.2\,ms over 48 layers), so the instrumentation
overstates the gap. The profiles' critical-path tables hold no usable rows, so these windows locate the difference
without decomposing it along a dependency chain.
