# Decode:相邻两步里,每层每个 expert 拿到的 token 数有没有联系?——GSM8K 实测(2026-09-15)

## 0. 问题与结论

问题:batch decode 时,第 t 步第 l 层 expert e 拿到 n 个 token,第 t+1 步同一层同一个 expert 是否也拿到差不多的数量?
(教授的判断:相邻 decode step 的 expert 激活相似,可以用前一步预测后一步。)

**结论:有,而且很强。**
1. 相邻两步、同一层的 128 维"每 expert token 数"向量,Pearson 相关 **0.87**(B=32,48 层均值;逐层 0.51–0.95),把 expert 编号打乱后为 0.00。
2. 相关随间隔慢慢衰减:隔 4 步 0.82,隔 16 步 0.76,隔 31 步仍有 0.41。
3. 条件分布:上一步拿 n 个 token 的 expert,下一步平均拿 **0.9 n**;上一步有 token 的 expert,下一步有 85% 仍有 token(无条件基准 48%)。
4. 单条序列看,同一层相邻两个 token 的 top-8 集合 Jaccard **0.30**(随机 8/128 的期望 0.03;换成另一条序列只有 0.15)。
5. 每一步内部仍然极不平均:最忙 expert 约 11 倍均匀份额,65/128 个 expert 为 0(与 prefill 的 §PREFILL_BALANCE 同量级)。

换句话说:**下一步会热的 expert,基本就是这一步热的那些**;但热的程度会波动(数量精确相等只有 54%,±1 以内约 50–85% 视 n 而定)。

## 1. 怎么测

| 项 | 设置 |
|---|---|
| 模型 | Qwen3-30B-A3B(48 层,128 expert,top-8),HF 权重,CPU bf16 |
| 数据 | GSM8K test 前 32 题(run 1)、第 33–64 题(run 2,复现)、前 8 题(run 3,B=8) |

## 3. 对课题的含义
- 用第 t 步的 per-expert 负载预测第 t+1 步是可行的:相关 0.87,active set 重合 72%。这支持"decode 按前一步的负载选一张预编好的图"的路线。
- 但预测的是"谁热",不是精确数量:数量精确相等只有 54%,所以图的 padding 仍要留余量;相关随步数衰减(16 步后 0.76,31 步后 0.41),换图周期在十几步量级。
- decode 每步内部和 prefill 一样极不平均(最忙 11× 均匀,一半以上 expert 空转),这是分档/子集激活的空间。

## 4. 限定
- CPU bf16 HF 模型的 routing,greedy 解码,不是卡上 MXFP6 图(logits 相关 0.85,个别路由可能翻转)。
- 只有 GSM8K,32 步;更长的生成、其它 workload 需另测。B=32 两组复现一致。
- B=8 的相关(0.72)偏低主要是 count 噪声(每步 64 个分配散在 128 个 expert 上);更大的 batch 会更高。
